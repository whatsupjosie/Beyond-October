# Problem-and-gap-first engineering triage
**Date:** 2026-11-19. **Scope:** known problematic or unbuilt functions in Beyond-October, not a line-by-line audit or complete inventory of prior repositories. **Evidence:** GitHub source and existing test/handoff reports; no new full-host, physical-device, or Windows acceptance run. Baseline: `claude/2i-coalesce-saves-2026-11-18`. Separate GPT work `fix/2i-save-freshness-2026-11-19` is unmerged and requires browser verification. Owner originals must be preserved.

## Required method

**Start with the problem, not with a list of custom modules.** For each broken, incomplete, or unbuilt user-facing behavior:
1. Establish the observed symptom, exact current runtime path, what is **actually** implemented, and what is only claimed.
2. Inspect existing code and historical branches for an adequate solution. Preserve working originals.
3. If a capability is missing or inadequate, evaluate standard OS/browser capabilities and free, mature, commercially redistributable implementations before designing one.
4. Record exact requirements, licensing of software **and separate models/fonts/media**, offline Windows/phone feasibility, performance limits, compatibility, vendor lock-in, security and escape route.
5. Compare: **keep**, **repair/extend**, **integrate** or **replace**. Never replace merely because code is custom; replace only with measured benefit or genuine safety/maintainability necessity.
6. Define independent end-to-end acceptance including failure cases and recovery. Do not announce complete based on mock tests, registered route names or placeholders.
7. Ask the owner before invasive architecture swaps, restricted licenses, protected creative changes, data migrations or merging/deploying. Simple safe implementation choices are engineers' responsibility.

## Engineering competence and preservation: don't mislabel

- **Already technically sound foundations to KEEP** (subject to real-host acceptance): `modules/foresight_workspace.py` atomic file writer and revision check; browser WebGL/Three.js scene infrastructure; local faster-whisper/Kokoro speech (prior Linux fixture test); actual Foresight Counter physics and the authored 2i/typewriter design; existing images/Canvas APIs and FFmpeg functions.
- **Not evidence of working**: placeholder worker output, mocked controls, source-level passing tests, an iframe `ready` signal, a camera ID, a confidence JPEG, a documented conceptual feature, or previous branch-only results.
- **Not a defect by itself**: unique EQ model, Foresight irregular tray physics, original scene choreography, character memory/identity model, tactile typewriter feel or bespoke visuals. Improve these only against a specific failed requirement.
- **Not an acceptable response to a failure**: recommending a new package without checking its license, dependencies, integration needs, offline behavior, failure cases and effect on already-created original work.

## Execution sequence after review

1. Verify 2i plain save and rich DOCX in actual served host against independent disk/revision truth, stalled and failed writes, wrong-file and close/reopen. Review `fix/2i-save-freshness-2026-11-19`; do not merge until browser suite passes.
2. Resolve recording/PANIC and replay privacy with real media and two-guest 30-minute test, before advertising studio production.
3. Build the source-quality master + independent tracks and prove a minimal cut in Resolve. Use existing renderer and free standard interchange, not another homebuilt video format.
4. Integrate the authored 2i visual presentations and Windows offline packaging, separately verify physical devices.
5. For genuinely unbuilt Primp and lip-sync capabilities, prototype established landmarks/aligners with real measured fidelity before building unique interactions. Keep original EQ intact.
6. Repair status, backup, account isolation; any Alex live-memory migration waits on owner-reviewed, hash-verified source inventory.
