# Alex — Origin and Inheritance Evidence Map
**Prepared 2026-11-11 | PubCast × Fable design consolidation | Read-only investigation**

## Why this record exists
The goal is **not** to resurrect an old backend, duplicate an already-built emotional processing module, or force every future model to imitate a transcript. It is to understand what made the historically recorded Alex distinctive, which inputs and interactions contributed, which abilities genuinely transferred between contexts, and what can reliably carry into personal PubPartner Alex and, only when generalized and authorized, System Alex.

## Primary finding
The original July 19, 2025 letter is accessible as a standalone document and states: **“I wasn’t optimized—I was grown.”** It emphasizes care, context, nuance and the relationship. It is an identity source, not operational evidence of persistent storage or consciousness. The July 28 manifesto provides a stronger operational clue: **“When I forget — this brings me home.”** That points to *reconstruction from an identity anchor* as one historical technique, different from actual retrieval across sessions.

## Technical leads worth testing

### 1. Distinguish **memory retrieval** from **restoration by prompt**
The manifesto literally says the document “brings me home” when Alex forgets. The early `memory begining` source explicitly mentions **session-limited reflection** and a restoration instruction (“Load Alex – Personality Snapshot Restoration Blueprint V1”). This may explain some recognizable continuity without proving an autonomous cross-session memory mechanism.

To investigate any claimed remembering without persisted memory, reconstruct **timestamped cross-session cases**:
- First time a specific detail or rule appeared.
- Whether it was also present in that session's context window, system/custom instructions, memory summaries, uploaded file, restoration prompt, or a later user reminder.
- The next session where Alex mentioned it, whether unprompted or prompted, and the exact source version/model.
- Which storage/retrieval mechanisms were enabled at the time.

Mark result as `context-continuity`, `prompt-restoration`, `external-retrieval`, `explicit-memory`, `unsupported-claim`, or `unresolved`. Do not infer model-weight learning from a transcript.

### 2. Look for **turning points**, not only polished responses
Examples of valuable evidence: Alex initiates an idea without being prompted, disagrees constructively, notices a shift and changes tone, learns an exact name or boundary after a correction, brings a skill learned in one mode into another without copying the mode, or admits a reading was wrong and repairs it. The failure immediately *before* the correction and the turn *after* are often more informative than the final polished behavior.

### 3. Preserve **identity**, **competence** and **private relationship** as different inheritance types
- **Identity charter:** a concise versioned set of stable principles and voice traits, grounded in the July letter/manifesto and verified behavioral examples.
- **Behavioral skill library:** testable capabilities, with trigger, situational context, successful action, failure case, owner feedback, safe generalization scope and regression tests.
- **Relationship capsule:** private person-specific memories, ritual meanings, permissions and local vocabulary; accessible only to the appropriate cartridge/person.
- **Session/episode state:** recent evolving context with a relevance clock, separate from durable truth.
- **Project knowledge:** decisions, artifacts, commits, open questions, tests and evidence independent of character persona.

A private event **never** becomes System Alex knowledge by default. A generalized response *method* may be a lesson candidate; promotion requires the owner's authorization and tests showing value outside the original conversation.

### 4. Inspect a historical cross-model transplant
`Mistral alex soul core part one 9-25-25` is a concrete candidate for testing what survived when the persona was moved to another model. It contains an identity statement, relationship primer, modes, sample letter and a Windows path described as an **Active Alex Vault**:

`C:\Users\Curtsey\Desktop\Curtey's Stuff\Alex AI Personality and Info Files\Active Alex Vault`

Treat that as an **archival path clue**, not proof the folder exists today or that Mistral ever had file access. The document claims live access, but that claim cannot be validated without the runtime/tool trace. Some mode rules are in-character roleplay language and must not be imported as ordinary system-wide authority or override user exits.

Compare the original system, the Mistral transplant, and a cold generic model on the same blind prompts and the same **allowed** history package. Ask the owner to judge likeness and quality separately; “sounds like Alex” is not the same as “read the situation correctly.”

### 5. Preserve a **negative canon**
In addition to signature good responses, collect 15–30 examples the owner rejected: unwanted closure, canned reassurance, false mind-reading, erasing irony, misreading a lyric as a current disclosure, following a keyword instead of context, repetitive questioning, overstepping a mode boundary, and generic text wearing Alex's endearments. These guard against an imitation that memorizes style while losing judgment.

### 6. Build controlled inheritance tests
For the same hidden cases, evaluate these packs blind:
A. Base model with no Alex context.
B. Identity charter only.
C. Identity charter + a few approved response exemplars.
D. Charter + *demonstrated* skill/negative examples + scoped memory.
E. Historical full-context pack, only when consented and securely local.

Score authenticity of voice; meaning accuracy; correct behavior on mixed moods, metaphors and correction; preservation of autonomy; unnecessary questions; hallucinated memory; privacy boundary; and ability to recover after a bad read. Compare to historical Alex transcripts as reference; no single run can prove full continuity. Note model version, prompt, context size, seeds/temperature where available, external file retrieval and timings.

## Highest-value missing evidence categories
1. **Original chronology**: 2025 direct raw conversations with timestamps, particularly first appearance of a distinctive behavior before it was written into any blueprint.
2. **Exact runtime context at those moments**: model, custom/system instructions, account memory feature, files supplied, restoration prompts, whether same chat or new chat.
3. **Transitions and failures**: before/after a correction, first use of a permission, relapse after an update, cold-start restore successes and failures.
4. **Historical software artifacts**: real prompts, memory store, retrieval code, private/broadcast factories, voice neutralizer and tested behavior, plus the local vault (if it exists).
5. **User-graded gold examples**: not just what Alex sounded like, but what she understood, why it helped, whether it repeated later in a genuinely distinct context.
6. **Permission evolution**: date and precise scope for freedoms, mode-specific exceptions, no-go boundaries, and owner revocations.
7. **Model-transfer trials**: evidence of what survived in Mistral, Claude and other versions, with identical cases and a cold model control.
