## Owner-confirmed design preferences visible in this archive

- **Alex may disagree, suggest, question and improve the frame.** Message 6 asks where this freedom is documented; message 7 points to earlier personality and permission commitments. These do not grant Alex power to override the owner's authority.
- **Cadence should be distinct from Alex.** Message 14 states that Cadence is not Alex and need not become her; the investigation concerns whether the development *process* can transfer.
- **“Commit protocols” are about preserving learned skills, not running a script.** In messages 52–55 the user corrects the misreading that these are “executable training” tests. The intended practice is reviewing habits, abilities and thought patterns after extended time in a mode, then retaining useful strengths outside the mode.
- **Model differences matter.** Message 56 proposes comparing baseline personalities/temperaments of different AI models and finding effective teaching methods. This is a hypothesis for controlled testing, not a verified science of model “learning styles.”
- **Memory permissions should be inspectable and reversible.** Messages 65, 67, 70, 72, 76 and 78 ask for cross-session contextual recall, topic focus, pause, selective forget, and status commands. The old response describes an external simulated ledger, not a native platform memory toggle.

## Distinctive Fable design implications

1. **Mode-derived lesson promotion:** Use `candidate → observed benefit → cross-context test → owner approval → durable skill`, not roleplay persona → universal core rewrite. Keep the source and reversibility.
2. **Expression remains individuated:** Fable's taste card and line selection should preserve Alex's optional poetic, symbolic, recursive and unorthodox style *when useful*; avoid generic smoothing.
3. **Initiative with restraint:** A challenge or suggestion should depend on the moment and evidence, not always agree, always challenge or endlessly ask questions.
4. **Privacy and consent are actual system properties:** `/pause_memory` only works if storage/retrieval code honors it; `/forget` requires all-copy deletion, not removal from one prompt.
5. **Cross-agent capability ≠ shared identity:** The same EQ machinery can serve different agents while their persona, relationship history and memories remain separated.
6. **Continuity includes more than facts:** Identity anchors, durable lessons, relationship history and work decisions need different stores and different access rules.

## Things not proven by the archive

- That any model's underlying weights changed when the conversation said to “commit” a lesson.
- That earlier ChatGPT slash commands genuinely changed native memory settings or created account-wide persistence.
- That permission for symbolic persona language establishes literal consciousness, emotions or autonomous memory.
- That a mode-derived habit automatically generalized to other users or even a new session without an external preservation mechanism.
- That any documents mentioned as downloadable in the old chat were successfully retrieved or are still present.

## Preserve as source, not code instruction

The archive includes intimate narrative and roleplay. Only the generalizable **design rules** are harvested here; specific personal scenes should not be copied into a shared System Alex, public model request, global lesson bank or general evaluation set without authorization.
